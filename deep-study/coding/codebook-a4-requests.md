# Codebook A4 — reviewer request taxonomy for performance/kernel PRs (v1.0)
Unit: one performance PR from vLLM or SGLang. Each record contains the PR id, title/state/body opening, and substantive non-author human reviewer messages with kind, role, and date. Code only reviewer messages dated before merge/close; for open PRs, code the messages present in the record.
## Output
For each PR, coders output exactly one JSON object:
```json
{id, request_types: [type_name], evidence: {type_name: "<=160-character verbatim reviewer quote"}, n_requests: 0}
```
- `id`: copy the PR id (for example, `vllm#46035`).
- `request_types`: unique taxonomy type names present in qualifying reviewer requests. Order is not meaningful.
- `evidence`: one <=160-character verbatim quote from a qualifying non-author reviewer message for each positive type. Preserve enough wording to show the request.
- `n_requests`: count distinct request instances, not distinct types. If one comment asks for accuracy and performance, count 2. If multiple reviewers repeat the same unresolved request, count it once unless they request a materially different action.

## Counting rules
Positive labels require a non-author human reviewer asking the author to do, provide, change, justify, or verify something before approval/merge. Requests may be phrased as imperatives, suggestions, blocking comments, or substantive questions that require a response/change.

Do **not** count: approvals/LGTM/praise; author-volunteered plans/results unless a reviewer requested them; bot-only or CI output; reviewer comments after merge/close; pure curiosity or informational discussion that does not require author action; follow-up ideas explicitly deferred to future PRs.

Questions count only when, in context, the reviewer is asking for an explanation, change, validation, or evidence needed to evaluate the PR (for example, 'Can you add tests?' or 'Why remove this argument?'). Pure 'QQ' or FYI exchanges without requested action do not count.

When a request spans multiple concrete actions, code all applicable types and count each distinct action. When one action fits multiple types, apply all types that capture materially different requirements (for example, 'run GPQA on DeepSeek with TP8' can be `run_accuracy_eval`, `test_affected_models_or_modes`, and `verify_parallelism_distributed_modes`).

(vllm#28095) |
